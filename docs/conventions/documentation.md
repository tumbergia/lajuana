# Convenciones de documentación

## Regla principal

Documentar estado real, no intención vaga.

## Cuándo actualizar documentación

- cuando cambie la estructura del repo;
- cuando cambie la arquitectura mobile o API;
- cuando se introduzca una convención nueva;
- cuando se tome una decisión técnica importante.

## Qué evitar

- documentos redundantes;
- duplicar información en varios archivos;
- texto de marketing interno;
- descripciones de cosas que aún no existen.
